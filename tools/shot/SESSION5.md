## ★ 정정 — 개발자 모드도 반드시 켜야 합니다

**이전 README/HANDOVER 는 "개발자 모드는 지금은 무관"이라고 적었습니다. 틀렸습니다.**

크롬 v151.0.7922.172 에서 **사용자 스크립트 허용은 켜 둔 채 개발자 모드만** 껐다 켜며
확인했습니다.

| 개발자 모드 | 사용자 스크립트 허용 | ART 화면 |
|---|---|---|
| 켜짐 | 켜짐 | **한국어** |
| **꺼짐** | 켜짐 | **영어** |
| 다시 켬 | 켜짐 | **한국어** |

**함정:** 개발자 모드를 꺼도 `chrome://extensions` 세부정보의
"사용자 스크립트 허용" 항목은 **화면에 그대로 남아 있고 스위치도 파란색 그대로**입니다.
켜져 있는 것처럼 보이는데 실제로는 동작하지 않고, 경고도 없습니다.

→ 설치 안내는 **항상 두 스위치를 함께** 말해야 합니다.

### 부수 발견 — `file://` 로 설치하려면 세 번째 스위치가 필요합니다

`.user.js` 파일을 크롬 창에 끌어다 놓아 설치하려면
**"파일 URL에 대한 액세스 허용"**(같은 세부정보 화면, 기본 꺼짐)도 켜야 합니다.
같은 파일로 이 스위치만 껐다 켜며 확인했습니다 — 껐을 때 무반응(설치 화면 자체가 안 뜸),
켰을 때 정상. 지금 가이드는 이 경로를 쓰지 않지만(붙여넣기 한 방법만 안내),
필요해지면 이 사실을 기억하십시오.

## ★★ 화면 자동화 사고 — 절대 반복하지 마십시오

**`SendKeys` 로 키보드 입력을 보내지 마십시오.**

이번 세션에서 크롬 창을 앞으로 가져와 주소를 타이핑하려고
`SetForegroundWindow` + `SendKeys` 를 썼습니다. 윈도우는 백그라운드 프로세스의
포그라운드 탈취를 막기 때문에 **창 전환이 조용히 실패했고, 키 입력이 그때 포커스를
갖고 있던 다른 앱(VS Code·카카오톡)으로 들어갔습니다.** 사용자에게 사과하고
카카오톡 대화방을 확인해 달라고 요청해야 했습니다.

또 하나의 실수: `Get-Process chrome | Where MainWindowTitle -ne ""` 로 창을 골랐더니
**사용자의 실제 크롬**이 먼저 잡혔습니다. 디버그용 크롬을 쓰려면 **PID 를 명시**하십시오.

### 대신 이렇게 하십시오 (`tools/shot/`)

| 파일 | 하는 일 |
|---|---|
| `cdpnav.js` | CDP 로만 조작. 키보드·포커스 안 건드림 |
| `winshot.ps1` | `PrintWindow` 로 창 내용만 캡처. 창을 앞으로 안 끌어옴 |

```bash
cd tools/shot
node cdpnav.js tabs                      # 탭 목록
node cdpnav.js nav "chrome://extensions/" # 이동 (chrome:// 도 됨)
node cdpnav.js scroll 900                 # 마우스 휠 스크롤
node cdpnav.js eval "document.title"      # JS 실행
node cdpnav.js shot out.png               # CDP 캡처 (chrome:// 은 불가)
node cdpnav.js altk                       # Alt+K 를 그 탭에만 전송
ART_TAB=1 node cdpnav.js eval "..."       # 탭 인덱스 직접 지정
ART_PORT=9333 node cdpnav.js ...          # 다른 디버그 크롬
```

```powershell
# chrome:// 페이지는 CDP 캡처가 막혀 있어 이걸 씁니다
.\winshot.ps1 -ProcId <크롬PID> -Out shot.png -Width 1560 -Height 1200
```

### 캡처할 때 걸린 함정 네 가지

1. **DPI.** 이 PC 는 150% 배율입니다. DPI 를 인식하지 않으면 `GetWindowRect` 는
   가상 좌표(1707×1067)를 주는데 `PrintWindow` 는 물리 픽셀(2560×1600)로 그려서
   **왼쪽 위 2/3 만 잘려 나옵니다.** `winshot.ps1` 은
   `SetThreadDpiAwarenessContext(-4)` 로 해결했습니다.
2. **창이 가려지면 빈 화면이 나옵니다.** 크롬이 백그라운드 창 렌더링을 멈춥니다.
   일반 https 페이지는 `cdpnav.js shot`(CDP 캡처)을 쓰면 창이 안 보여도 잡힙니다.
3. **CDP `nav` 는 탭을 바꾸지 않습니다.** 이동시킨 탭과 화면에 보이는 탭이 다를 수
   있습니다. `cdpnav.js` 는 `/json/activate` 를 먼저 호출해 해결했습니다.
4. **인포바.** 유저스크립트 설치 페이지를 다녀오면
   "이 웹사이트에서 앱·확장 프로그램을 추가할 수 없습니다" 줄이 남아 레이아웃이 밀립니다.
   `/json/new` 로 **새 탭을 만들고 기존 탭을 닫으면** 깨끗해집니다.

## 설치 가이드 구조

`tools/shot/install-tpl.html` 이 본문 템플릿입니다.
**`ART-한글판-설치가이드.html` 을 직접 고치지 마십시오** — `build-guide.py` 가 덮어씁니다.

가이드는 **5단계**입니다.

1. 크롬 웹스토어에서 Tampermonkey 설치
2. **개발자 모드 켜기**
3. Tampermonkey 세부정보 열기
4. **사용자 스크립트 허용 켜기**
5. 스크립트 붙여넣기 (페이지 안의 **전체 복사** 버튼 → 대시보드 → ＋ → `Ctrl+A` → `Ctrl+V` → `Ctrl+S`)

### 설치 방법이 하나뿐인 이유

처음에는 "로컬 서버로 설치"를 대안으로 넣었다가 뺐습니다. **성립하지 않는 방법이었습니다** —
`python -m http.server` 를 하려면 `.user.js` 파일이 이미 손에 있어야 하는데,
가이드를 받은 사람에게 없는 게 바로 그 파일입니다. 파이썬도 필요하고요.
그다음 "파일로 저장해서 끌어다 놓기"를 넣었다가 사용자 판단으로 그것도 뺐습니다.
**지금은 붙여넣기 한 방법뿐이고, 그게 맞습니다.**

### 스크립트 전문을 페이지에 심는 이유

아티팩트 뷰어는 **페이지가 시작하는 다운로드를 차단합니다.** `<a download>` 도
data:/blob: 도 동작하지 않습니다. 그래서 파일을 링크로 줄 수 없고,
`ART_SRC` 문자열로 심어 **클립보드 복사**로 전달합니다.
복사 버튼은 3단계로 물러납니다 — `navigator.clipboard` → `execCommand('copy')` →
텍스트 칸을 펼쳐 전체 선택(`Ctrl+C` 안내).

`json.dumps` 후 **`<` 를 `<` 로 바꿔야** 소스 안의 문자열이 `</script>` 로
오인되지 않습니다. `build-guide.py` 가 처리합니다.
